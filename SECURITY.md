# Security

## Secure Tool Registry

- Read-only discovery tools may run without confirmation.
- Validated local actions can open only concrete files, discovered applications, or discovered projects.
- Stored project startup commands require explicit confirmation in the same browser session and expire after five minutes.
- Inputs reject unknown fields and invalid sizes before reaching a service.
- Unknown tools are rejected and audited.
- No unrestricted command or shell tool is registered.
- Tool attempts, validation failures, permission decisions, and results are written to the local structured audit log.

- Never commit `.env`; it contains your Gemini API key.
- Do not expose the local server to the internet without authentication and HTTPS.
- App launching is allowlisted. Keep it that way.
- This project intentionally does not run arbitrary terminal commands generated by an LLM.
- Review any future file-editing or browser-automation action before enabling automatic execution.
- Revoke and replace a key immediately if it appears in a screenshot, Git commit, or public message.
# Phase 3 mission security

Mission plans cannot invoke operating-system services directly. Every actionable step uses the Phase 2 Secure Tool Registry with strict argument models and audit logging. Documents are restricted to configured search roots and supported non-executable formats; macros and document contents are never executed. Clarifications are bound to the originating browser session, and local actions are never retried automatically.
