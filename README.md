# Odysseus v6 — Desktop Intelligence Foundation

## Phase 2 secure tool execution

All file, application, and project actions now pass through a central Secure Tool Registry. Every tool has strict typed arguments, an explicit permission level, a timeout, health information, and a structured audit entry. Unknown tools and extra arguments are rejected. Project startup commands require a session-bound confirmation that expires after five minutes. There is no arbitrary shell tool, and Gemini cannot call operating-system services directly.

The Phase 1D automatic browser-opening issue remains a documented Windows limitation and is not claimed as fixed by Phase 2.

Odysseus v6 begins the backend rebuild around **real desktop tools** rather than cosmetic agent labels. It preserves the purple/black mission dashboard from v5, but adds concrete Windows capabilities.

## Phase 3 mission reliability

Every registered mission tool has an enforced deadline. A blocked file,
application, project, document, or Gemini operation now fails with a visible
reason instead of leaving the mission in `running`. Unexpected background
errors are persisted as failed mission steps, and dashboard polling failures
are displayed in the conversation.

## What v6 can actually do

### 1. Intelligent local file search

Odysseus searches these folders automatically:

- Desktop
- Documents
- Downloads
- the folder configured as `PROJECT_SCAN_PATH`
- optional folders listed in `FILE_SEARCH_ROOTS`

Examples:

```text
Open my microbiology notes
Open my latest resume
Find the PCR PDF I downloaded last week
Show me my Python notebook
```

Matching uses filename words, fuzzy similarity, file type, folder name, and modification time. If one result is clearly best, Odysseus opens it. If several results are plausible, it displays up to five choices and waits for a number.

Example:

```text
You: Open my microbiology notes
Odysseus: I found these matches:
1. Microbiology_Unit_1.pdf — C:\Users\...\Documents
2. Microbiology_Notes.docx — C:\Users\...\Downloads

Reply with the number of the file to open.
You: 1
Odysseus: Opening Microbiology_Unit_1.pdf.
```

Odysseus does not execute the file. It asks Windows to open it using the associated application.

### 2. Installed-application discovery

Odysseus discovers applications from Windows Start Menu shortcuts, common installation locations, and safe Windows registry metadata. It ranks matches, understands user-defined aliases, and asks for a numbered choice when a name is ambiguous. This avoids maintaining hardcoded paths for every installed program.

Examples:

```text
Open Postman
Launch Jupyter Notebook
Start Docker Desktop
Open Spotify
```

Discovery is local and does not upload your application list.
Launch attempts and their outcomes are written to the local tool audit log.

### 3. Intelligent project and folder discovery

Odysseus scans configured parent folders, recognizes common project markers, identifies the technology, ranks name matches, and opens the selected folder in VS Code when available. Similar names produce a numbered choice. Discovery is bounded by a directory limit and timeout, and generated folders such as `node_modules`, `.git`, virtual environments, and build output are excluded.

Examples:

```text
Find my Odysseus project
Open project biotech hub
Open my college folder
Discover projects
```

Register an alias when you want a shorter permanent name:

```text
Register C:\Users\DELL\Projects\BiotechAI as my biotech project
Continue my biotech project
List projects
```

Phase 1D adds persistent workflow profiles. Each registered project can store a preferred editor, an optional startup command, a localhost URL, and up to ten recent session notes. Odysseus can also report the Git branch/change count and detect README/TODO files.

```text
Set Visual Studio Code as editor for my biotech project
Set startup command for my biotech project to python app.py
Set URL for my biotech project to http://127.0.0.1:8000
Add note for my biotech project: finish the quiz endpoint
Show status for my biotech project
Continue my biotech project
```

Startup commands are never run immediately and are never generated by Gemini. After `Continue`, Odysseus displays the stored command and requires `Confirm`; `Cancel` leaves it untouched. After confirmation, a configured localhost URL is checked until the server is ready and then opened automatically in the default browser. Odysseus reports an occupied port, an early process exit, or a readiness timeout instead of silently failing.

When VS Code's `code` command is available, the project opens directly in VS Code. Otherwise, its folder opens in the default file manager.

To register the folder configured in `PROJECT_SCAN_PATH`:

```text
Register this folder as my main project
```

### 4. Tool execution audit

Desktop actions are recorded locally in:

```text
app/data/tool_audit.jsonl
```

Each record contains the time, tool name, validated inputs, outcome, and user-facing message. API keys are never written to this log.

### 5. Existing capabilities retained

- Gemini conversation and diagnostics
- Mission Engine
- Project Intelligence scan
- SQLite memory
- system telemetry
- web search
- browser voice input/output

## Important scope statement

v6 implements the **first real desktop milestone**. It does not yet include complete document extraction, multi-step tool planning, scholarly research retrieval, unrestricted terminal execution, or a native desktop wrapper. Those are later milestones. The goal of this release is to make file and application access genuinely useful and verifiable.

## Setup

1. Extract the ZIP into a new folder. Do not merge it into v5.
2. Copy `.env.example` and rename the copy to `.env`.
3. Add your existing Gemini key:

```env
ASSISTANT_NAME=Odysseus
GEMINI_API_KEY=YOUR_EXISTING_KEY
GEMINI_MODEL=gemini-flash-latest
PROJECT_SCAN_PATH=.
```

4. Optional extra file-search folders use semicolons:

```env
FILE_SEARCH_ROOTS=C:\Users\DELL\College;C:\Users\DELL\Projects
PROJECT_SEARCH_ROOTS=C:\Users\DELL\Projects;C:\Users\DELL\Documents
```

5. Run:

```powershell
.\run.bat
```

6. Open `http://127.0.0.1:8000` if the browser does not open automatically.

## Architecture

```text
Natural-language command
        ↓
Deterministic intent router
        ↓
Safe tool boundary
 ┌──────────────┬────────────────┬─────────────────┐
 │ File Finder  │ App Discovery  │ Project Registry│
 └──────────────┴────────────────┴─────────────────┘
        ↓
Validation + execution
        ↓
Local audit record + UI response
```

Gemini is used for general language and mission reasoning. It does not receive unrestricted shell access.

## Main new files

- `app/services/file_finder.py` — searches, scores, and opens matching files.
- `app/services/app_launcher.py` — built-in app allowlist plus Windows Start Menu discovery.
- `app/services/project_registry.py` — discovers, identifies, ranks, aliases, and safely opens project folders.
- `app/services/tool_audit.py` — append-only local action log.
- `app/services/intent_router.py` — routes file, app, and project commands before Gemini chat.

## Privacy and safety

- Local filenames and paths remain on your computer during ordinary file search.
- No destructive file operations are included.
- Odysseus never runs files found by search; it opens them with Windows.
- Terminal commands are not generated or executed by Gemini.
- `.env`, databases, project mappings, and audit logs are ignored by Git.

# Phase 3 — Mission Engine

This checkpoint adds persistent, real multi-step missions. The dashboard polls actual backend state; a step is completed only after its Secure Tool Registry action succeeds.

Supported end-to-end workflows:

- Study a `.txt`, `.md`, `.pdf`, or `.docx` document and generate a grounded summary plus five revision questions.
- Continue a project, inspect its status, open it, and record the session.
- Discover and launch multiple applications sequentially and report what launched.

Mission clarification and confirmation are browser-session bound, expire after ten minutes, and can be cancelled. History is stored locally in `app/data/mission_history_v3.json`. Document extraction is bounded by allowed roots, file size, pages, and text length. Gemini must be connected for study-material generation.
